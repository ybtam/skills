Agreed contract

DecisionApproved behavior
Entry pointssetup-repo, adopt-standards, upgrade-standards, and migrate-to-monorepo inspect first, ask release intent, and conditionally invoke the new skill.
Setup orderInstall and verify selected skills, then trigger grill-with-docs. Where the host requires explicit invocation, request it rather than claiming it ran. Every entrypoint retains a bundled fallback when a supporting skill is unavailable.
Release topologyThe owner selects one repository release, independent packages/apps, named fixed/linked groups, and any explicitly ignored packages. Changesets selects only descriptor-backed, selected units.
PythonA private package.json sidecar coordinates release data only. The skill never edits pyproject.toml, synchronizes Python versions, or claims PyPI publication.
PublicationThe owner selects version PR only, GitHub Release, or registry publication. Missing registry/access/auth answers leave publication unconfigured.
Release ownerExactly one: native Changesets or one explicit, rerunnable repository release script. No duplicate tags or releases.
ProductionRepository-owned and optional. Per ADR 0002, the baseline trusts the selected Changesets release event and adds no independent tag or commit validation.

Verification contract

Local checks after approval

  • Install the CLI with Bun and update only bun.lock.
  • Run bun run skills:bundle then bun run skills:check.
  • Run real Changesets fixtures without publish commands.
  • Run typecheck, tests, lint, format check, and site build.
  • Review the working tree and run git diff --check.

Target workflow invariants

  • No release setup before explicit release intent.
  • Only selected release units are configured.
  • One tag/GitHub Release owner per path.
  • Mutating release CI is branch-gated and non-cancellable.
  • Prerelease publication/deployment is explicitly selected.
  • Registry jobs wait for all required owner inputs.
Local result ≠ remote CI ≠ registry publication ≠ GitHub Release ≠ production deployment
